# Fundamentals of Computers and Programming

## Course Goal

Students learn how computers work, how to solve problems step by step, and how to build practical applications using Python, GitHub, files, databases, and introductory AI concepts.

The course should stay practical, example-driven, quiz-friendly, and focused on fundamentals instead of heavy theory.

## Learning Outcomes

By the end of the course, students will be able to:

- Explain how computers process information and run programs.
- Use computational thinking to break down problems.
- Design algorithms using pseudocode and flowcharts.
- Write Python programs using variables, conditions, loops, functions, and data structures.
- Read from and write to files.
- Debug and test programs systematically.
- Use GitHub and an IDE to organize, track, and share code.
- Understand basic object-oriented programming principles.
- Explain the purpose of front end, middle tier, and back end layers.
- Understand basic SQL and NoSQL database concepts.
- Discuss ethics, cybersecurity basics, and responsible AI use.

## Teaching Format

Each class should follow a simple rhythm:

1. Short concept introduction
2. Instructor demo
3. Hands-on activity
4. Quick quiz or reflection
5. One thought-provoking question

## Module 1: How Computers Work

Students learn what a computer does when it runs a program.

**Core Topics**

- Input, processing, output, and storage
- Binary, bits, bytes, decimal, and hexadecimal
- CPU, RAM, storage, motherboard, and devices
- RAM vs SSD/HDD
- Operating systems, files, programs, and processes
- Compilers, interpreters, and why programming languages exist

**Practice**

- Convert decimal numbers to binary.
- Explore Task Manager or Activity Monitor.
- Compare RAM and storage using real-life examples.
- Use a logic gate simulator for AND, OR, and NOT.

**Think About**

If computers only understand 0s and 1s, how can they show images, videos, and games?

## Module 2: Computational Thinking and Algorithms

Students learn how to solve problems before writing code.

**Core Topics**

- Problem decomposition, pattern recognition, and abstraction
- Algorithm design
- Pseudocode and flowcharts
- Sequence, selection, and iteration
- Searching and sorting
- Time and space complexity at a beginner level

**Practice**

- Write an algorithm for making a sandwich.
- Create a flowchart for ATM withdrawal.
- Design pseudocode for a quiz app.
- Compare linear search and binary search using a classroom activity.
- Create a flowchart and pseudocode for a grade calculator.

**Think About**

Can two correct algorithms solve the same problem, but one be better than the other?

## Module 3: Python Programming Basics

Students begin writing simple working programs.

**Core Topics**

- Running Python code in an IDE
- Comments and basic program structure
- Variables and data types: integer, float, string, boolean
- Type conversion and operators
- Input and output
- Conditions: `if`, `else`, `elif`
- Loops: `for`, `while`

**Practice**

- Build a temperature converter.
- Build a simple calculator.
- Build a number guessing game.
- Build a password strength checker.
- Build a grade calculator.

**Think About**

Why do small mistakes in code sometimes cause big failures?

## Module 4: Functions and Data Structures

Students learn to write reusable code and organize data.

**Core Topics**

- Functions, parameters, return values, and scope
- Lists, dictionaries, sets, and arrays
- Stacks: last in, first out
- Queues: first in, first out
- Trees and graphs at a beginner conceptual level

**Practice**

- Create a contact book using dictionaries.
- Build a shopping cart using lists.
- Write functions for calculator operations.
- Use a set to remove duplicate names.
- Use a stack to model undo history.
- Use a queue to model students waiting for help.
- Build a student record manager with add, search, update, and display options.

**Think About**

Why is choosing the right data structure sometimes more important than writing more code?

## Module 5: Files, Debugging, and Testing

Students learn how programs save data and how programmers find mistakes.

**Core Topics**

- Reading and writing text files
- CSV files and data persistence
- Syntax errors, runtime errors, and logical errors
- `try/except`
- Print debugging and IDE debugger basics
- Test cases and edge cases

**Practice**

- Save student grades to a CSV file.
- Debug intentionally broken programs.
- Create test cases for a calculator.
- Build a simple expense tracker using files.

**Think About**

Can a program run successfully and still be wrong?

## Module 6: Object-Oriented Programming

Students learn how programs can model real-world things.

**Core Topics**

- Classes and objects
- Attributes, methods, and constructors
- Encapsulation
- Inheritance
- Polymorphism at a beginner conceptual level
- When object-oriented programming is useful

**Practice**

- Create a `Student` class.
- Create a `BankAccount` class.
- Create a simple game character class.
- Convert a dictionary-based contact book into an object-based design.

**Think About**

Is a class more like a blueprint, a factory, or a real object?

## Module 7: Databases: SQL and NoSQL

Students understand how real applications store and retrieve data.

**Core Topics**

- Why files are not enough for larger applications
- What a database is
- SQL databases: tables, rows, columns, and primary keys
- Basic SQL: `SELECT`, `INSERT`, `UPDATE`, `DELETE`
- NoSQL databases: documents and key-value data
- SQL vs NoSQL: when to use each

**Practice**

- Design a student table.
- Write simple SQL queries.
- Compare a SQL table with a JSON document.
- Build a small app that stores records in SQLite.

**Think About**

Should a social media app store profiles, posts, and comments in tables, documents, or both?

## Module 8: How Real Applications Are Built

Students understand the structure of modern software applications.

**Core Topics**

- What an application is
- Front end: forms, buttons, pages, and screens users interact with
- Middle tier: validation, calculations, rules, permissions, and workflows
- Back end: files, databases, servers, and stored data
- APIs, requests, and responses at a beginner level
- Example architectures: food delivery app and school management system

**Practice**

- Draw the architecture of an online shopping app.
- Draw the architecture of a school portal.
- Draw the architecture of a movie ticket booking app.
- Draw the architecture of a chat app.
- Build a simple 3-tier style app with a menu or page, Python logic, and file or SQLite storage.

**Think About**

Why should the user interface and database not be mixed together in one place?

## Module 9: GitHub and Software Engineering Practices

Students learn how programmers organize, track, and share code.

**Core Topics**

- Introduction to the Software Development Life Cycle: how an idea becomes working software
- SDLC stages: requirements, design, implementation, testing, deployment, and maintenance
- Git basics: repository, commit, branch, merge
- GitHub basics
- README files
- Code comments
- Peer review

**Practice**

- Map a simple app idea through the SDLC stages.
- Create a GitHub repository.
- Make commits after each feature.
- Write a README file.
- Review a classmate's code.
- Fix a bug from feedback.

**Think About**

Why do professional programmers save code history instead of only saving the final version?

## Module 10: Ethics, Cybersecurity, ML, and Generative AI

Students learn about responsible computing and modern AI.

**Core Topics**

- Data privacy, password safety, and cybersecurity basics
- Open-source software and intellectual property
- Algorithmic bias and responsible AI
- Machine learning: training data, model, prediction
- Classification and recommendation examples
- Generative AI: prompts, responses, limitations, and hallucination
- Human responsibility in AI use

**Practice**

- Test how changing a prompt changes AI output.
- Discuss bias in recommendation systems.
- Build a simple rule-based chatbot.
- Compare rule-based logic with ML-based prediction.
- Analyze an AI-generated answer for accuracy.

**Think About**

If an AI gives a wrong answer, who is responsible: the AI, the user, the developer, or the company?
